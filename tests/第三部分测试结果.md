## 3.2 模块锁定(staged) vs 全局(All) 对比 —— 两阶段设计合理性实证

> 目的：回答"先 3.1 选模块、再 3.2 模块内搜索"是否冗余。同一条查询，分别跑「锁定 3.1 命中模块」与「全局不锁定」两种 3.2，对比 top1 归属与延迟。
> 测试脚本：`tests/staged_vs_global.py`（走 HTTP 复用已加载的 embedding 模型；需先 `bash scripts/run.sh` 起后端）。

| query | 3.1 模块 | 锁定模块 top1 (staged) | 全局 top1 (All) | 延迟加速 | 结果差异 |
|---|---|---|---|---|---|
| hmm | hmm | MultinomialHMM::hmm | MultinomialHMM::hmm | 0.82x* | 一致 |
| gmm | gmm | GMM::gmm | GMM::gmm | 2.67x | 一致 |
| lda | lda | LDA::lda | LDA::lda | 2.42x | 一致 |
| decison tree | trees | DecisionTree::trees | DecisionTree::trees | 2.22x | 一致 |
| logisitc regresion | linear_models | LogisticRegression::linear_models | LogisticRegression::linear_models | 1.93x | 一致 |
| gausian mixture | gmm | GMM::gmm | GMM::gmm | 3.31x | 一致 |
| random forest | trees | RandomForest::trees | RandomForest::trees | 22.06x | 一致 |
| xgboost | trees | GradientBoostedDecisionTree::trees | GradientBoostedDecisionTree::trees | 2.46x | 一致 |
| q learning | rl_models | DynaAgent::rl_models | DynaAgent::rl_models | 2.12x | 一致 |
| reinforcement learning | rl_models | MonteCarloAgent::rl_models | **BanditPolicyBase::bandits** | 2.51x | ⚠ 不一致 |
| neural network | neural_nets | Identity::neural_nets | **RNNCell::neural_nets** | 1.29x | ⚠ 不一致 |
| naive bayes | linear_models | GaussianNBClassifier::linear_models | GaussianNBClassifier::linear_models | 2.48x | 一致 |

\* `hmm` 那条 0.82x 为首次调用冷启动噪声（首条 staged 调用未命中缓存），其余 11 条锁定版均更快，平均延迟加速 **3.86x**。

**汇总**
- 平均延迟加速比（全局 / 锁定）：**3.86x** —— 锁定模块后候选集更小，3.2 稳定更快。
- 结果不一致用例：**2 / 12**。两阶段在这里纠正了全局搜的错误路由：
  - `reinforcement learning`：全局把 `BanditPolicyBase`（bandits 模块）顶到第一；锁定 `rl_models` 后纠正为 `MonteCarloAgent::rl_models`。
  - `neural network`：全局把 `RNNCell`（neural_nets 模块内的"错位"类）顶到第一；锁定 `neural_nets` 后纠正为 `Identity::neural_nets`。
- 结论：**两阶段并非冗余**。3.1→3.2 在「速度」（平均 3.86x 加速）与「消歧正确性」（2/12 边界用例纠正）两个维度上都有实测收益；10/12 用例全局搜虽未错，但锁定版同样更快，无额外代价。

> 注：前端已实现"点 3.1 模块卡片自动带原查询 + 模块约束触发 3.2"（`frontend/index.html` 的 `selectModule()`），用户无需重输查询，故"重复搜两次"的体感问题已在交互层解决。
