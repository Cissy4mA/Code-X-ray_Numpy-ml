# Code X-Ray 小组分工方案（12 个分工 / 6 人）

## 一、总原则
- 6 个人，每人 2 个坑，合计 12。
- 项目统筹（组长）领 2 个：**检索精度提升**（最难、最见技术含量，亲自做）+ **统筹监督**（每块都盯、缺哪儿补哪儿）。
- 其余 5 人各领 2 个功能坑（共 10 个）。
- 后端 = 技术深度，前端 = 呈现效果。
- 每个人随时用中文记自己那块的流水账，**不要求严谨和格式**，话越直白、越细越好；最后统一发给「论文主笔」拼成正文。
- 前后端约定：**前端想要的新功能，先和后端商量定好接口，再做页面**。

## 二、12 个分工清单

### 后端组（技术深度）
1. **检索精度提升**
   - 优化 embedding（模型 / 切分策略 / 维度）、混合检索权重、重排序。
   - 目标：让算法搜索 top-k 命中更准，论文有真东西可写。
   - 这是全项目最难、最有技术含量的板块，由负责人亲自扛。
2. **学习板块功能开发**（2 人）
   - 在 Learn 模块补：数学原理卡片、算法对比、学习路径、调用关系图。
   - 出后端接口，交给前端「学习板块可视化」做呈现。
3. **检索评估与测试保障**（1 人）
   - 做评测查询集 + 标注答案，算命中率 / MRR，给检索精度提升量化背书。
   - 后端接口冒烟测试，保证演示当天 8000 端口常驻不挂。

> 注：数据库导入与维护由 agent 直接完成，不单列分工，无难度。

### 前端组（呈现效果）
4. **整体页面设计与美化**（1 人）
   - 主题色、布局、组件样式，决定产品第一眼质感。
5. **检索结果可视化**（1 人）
   - Search 页：模块搜索原样渲染 GitHub README；算法搜索 top-k 用卡片 / 高亮呈现。
6. **学习板块可视化**（1 人）
   - Learn 页：把数学卡片、算法对比、学习路径、调用关系图做成交互页面。

### 论文组
7. **论文主笔与统稿**（1 人）
   - 收齐 6 个人流水账，整理成正式论文正文、结论与摘要。
8. **论文排版与配图**（1 人）
   - 套课程模板（LaTeX / Word）统一格式；画系统架构图、检索流程图、6 表 ER 图、结果对比图。

### 视频组
9. **视频演示录制**（1 人）
   - 走查：导入 → 搜索（模块 / 算法）→ 学习板块 → 结果展示，录屏。
10. **视频剪辑与配音**（1 人）
    - 剪冗余、加旁白 / 字幕 / 配乐，出最终演示视频。

### 统筹组
11. **项目统筹与质量把控（跨板块检查）**
    - 每块都盯进度，定期检查交付物，哪儿缺人负责人顶上、哪儿卡住负责人协调。
    - 把关前后端接口对齐：提醒前端先找后端定接口再做页面。
    - 统一验收标准，整合前检查各模块是否真正连通（前端能跑通后端）。
    - 串起论文和视频时间线，确保交稿 / 交片不冲突。

**合计：后端 4（统筹占 1 + 学习 2 + 评估 1）+ 前端 3 + 论文 2 + 视频 2 + 统筹 1= 12 ✓**

## 四、每人流水账记录模板（随时记，中文，越细越好）
```
【日期】2026-09-17
【负责】检索精度提升（分工 1）
【今天干了啥】
- 把 embedding 模型从 all-MiniLM 换成 xxx，top-1 命中 60%→75%
- 混合检索权重改成 关键词 0.4 + 语义 0.6，感觉更准
【踩的坑】
- 切分太长导致向量被截断，改短后就好了
【明天打算】
- 加个重排序再试
【给论文主笔的原话】（直接复制这段就行）
今天调了 embedding……（口语化写，不用改）
```
要点：不管标点格式，**把“做了啥、改了哪个文件/参数、结果变好还是变坏、卡在哪”写清楚**即可。

## 五、论文汇总流程
1. 每个人从第一天起就按模板记，不用等完工。
2. 主笔（分工 7）交稿前 3~4 天发群提醒：所有人把流水账发过来。
3. 主笔把 6 份流水账 + 配图（分工 8）+ 评估数字（分工 3）拼成初稿。
4. 排版配图（分工 8）套模板出 PDF，定稿。

## 六、前三周工作安排（研发期，论文/视频暂缓）

**总目标**：3 周内做到 80% 乃至完成产品。论文组（7/8）、视频组（9/10）这 3 周**不启动**，第 4 周再接。
**核心触发规则**：后端功能一做完 → 统筹立刻发群 → 前端开始优化 / 可视化落地、测试开始跑。

### 第 1 周：后端打底 + 前端并行启动
**后端（检索精度 1 人 + 学习开发 2 人）**
- 检索精度（分工 1）：启动 embedding / 混合检索 / 重排，目标本周出可跑初版。
- 学习开发（分工 2，2 人）：数学卡片 / 对比 / 路径 / 调用图接口开发，目标本周出接口。
- 目标：第 1 周末后端核心功能完成。

**前端（3 人）并行，不等后端**
- 分工 4 页面设计美化：直接做静态视觉 / 布局 / 主题（不依赖接口）。
- 分工 5 检索结果可视化：后端结果未出，先收集案例、积累素材、准备渲染模板。
- 分工 6 学习板块可视化：同理，收集案例、积累素材。

**测试（分工 3 检索评估与测试保障）**
- 查资料：选什么指标验证（命中率 / MRR / Precision@k 等）。
- 规划：做哪些可视化图来在论文里描述测试结果。
- 搭评测集框架（查询 + 标注答案）。

**统筹**：盯后端进度；后端功能一完成，**立刻发群**通知前端优化、通知测试开测。

### 第 2 周：功能基本完善 + 美化/可视化基本完善
**后端**
- 检索精度负责人：基于测试反馈把检索精度再提一轮。
- 学习开发：接口稳定、补齐边界 case。

**前端**
- 分工 4：页面美化完成。
- 分工 5 / 6：接后端真实接口，把检索结果 / 学习板块可视化落地。

**测试**：跑评测集、出指标数字、出可视化图，反馈给后端检索精度负责人。

**统筹**：组织前后端联调，确保前端能跑通后端。

### 第 3 周：继续完善，冲完成
- 后端：细节打磨、难 case 处理。
- 前端：美化 / 可视化查漏补缺。
- 测试：补指标、补图。
- 统筹：逐模块验收，第 3 周末产品达到 80% ~ 100%。
- （第 4 周起再启动论文 / 视频，不在本计划范围。）

**依赖提醒**：前端（4/5/6）的真实接口渲染必须等后端（分工 1 / 分工 2）接口定了再动；第 1 周前端做的是静态视觉 + 素材积累，不算返工。

## 七、容易翻车的提醒
- 视频录制当天后端必须能跑，分工 3 和 9 提前对好时间。
- 检索精度提升必须有分工 3 的数字背书，否则论文这句话站不住——负责同学坐近点。
- 所有人流水账早点记，别等主笔催——主笔最怕交稿前收到一堆空白。
- 统筹身兼检索精度 + 统筹，重点是**别让任何一块掉链子**，尤其前后端接口对齐和演示环境常驻。
